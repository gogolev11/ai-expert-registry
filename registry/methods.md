## Экономия токенов и денег

### Кэширование повторяющегося начала запроса (prompt caching)
- **id:** `prompt-caching`
- **Тип:** метод
- **Что это:** неизменную часть (системный промпт, инструменты, длинные документы, примеры) ставить в начало запроса и кэшировать.
- **Механизм:** провайдер не обрабатывает заново закэшированный префикс; у Claude чтение из кэша ~10 % цены обычного входа.
- **Как применять:** статичное — первым, меняющееся (дата, данные запроса) — в конец; не менять инструменты и системный промпт между вызовами.
- **Статус:** active
- **Источники:** https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Маршрутизация по сложности (дешёвая модель / decision-модель для простого)
- **id:** `model-routing`
- **Тип:** метод
- **Что это:** простые подзадачи (классификация, выбор пути, извлечение) отдавать дешёвой модели или decision-модели, сложные — флагману.
- **Механизм:** цена разных моделей отличается в десятки раз (например, GPT-6 Luna ~$0.10 vs Astra ~$10 за 1M входа; Claude Haiku 5.5 $0.10 vs Opus 5.5 $4; Jev — $0.042 вход, выход бесплатно). Decision-модели вроде Jev / OpenAI Decisions API возвращают выбор вместо текста — меньше токенов вывода, быстрее, предсказуемее.
- **Как применять:** сначала измерить качество дешёвой модели на 20–50 реальных примерах; маршрутизировать только то, где она не хуже.
- **Статус:** active
- **Источники:** https://openrouter.ai/typesafe/jev-1.13 · https://openai.com/index/devday-2026-recap/ · https://platform.claude.com/docs/en/about-claude/pricing
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-08

### Пакетная обработка (Batch API)
- **id:** `batch-processing`
- **Тип:** метод
- **Что это:** не срочные массовые запросы отправлять пакетом.
- **Механизм:** провайдер выполняет пакет в удобное ему время и даёт скидку (Claude — 50 %; результат обычно за час, максимум 24 ч).
- **Статус:** active
- **Источники:** https://platform.claude.com/docs/en/build-with-claude/batch-processing
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Инструменты как код вместо сотни описаний в контексте (code execution with MCP / tool search)
- **id:** `code-execution-tools`
- **Тип:** метод
- **Что это:** не загружать описания всех инструментов в контекст, а давать агенту находить нужные по запросу и вызывать их кодом; большие промежуточные данные обрабатывать в среде выполнения, а в модель возвращать только итог.
- **Механизм:** описания инструментов и промежуточные результаты больше не проходят через контекст модели. Anthropic: пример Google Drive → Salesforce сократился со ~150 000 до ~2 000 токенов (−98,7 %). Сопутствующая рекомендация (OpenAI, через вторичный источник): точность падает при >10 инструментах, держать <20 на агента.
- **Статус:** active
- **Источники:** https://www.anthropic.com/engineering/code-execution-with-mcp · [вторичный] https://www.newsletter.swirlai.com/p/state-of-context-engineering-in-2026
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Постепенное раскрытие контекста через Skills
- **id:** `progressive-disclosure`
- **Тип:** метод
- **Что это:** вместо огромного системного промпта — набор Skills: в контексте только имена и описания, полный текст загружается, когда задача подходит.
- **Механизм:** [вторичный] описание Skill ~80 токенов против 275–8 000 токенов полного текста — платите за полный текст только когда он нужен.
- **Статус:** active
- **Источники:** https://agentskills.io/specification · [вторичный] https://www.newsletter.swirlai.com/p/state-of-context-engineering-in-2026
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Сжатие истории (compaction) с сохранением ошибок
- **id:** `context-compaction`
- **Тип:** метод
- **Что это:** в длинной сессии старую историю суммаризировать, последние шаги оставлять дословно.
- **Механизм:** меньше токенов на каждом шаге и меньше «шума» для модели. Важная деталь (Manus): ошибки и последние вызовы инструментов не сжимать — иначе агент повторяет те же ошибки.
- **Статус:** active
- **Источники:** [вторичный] https://www.newsletter.swirlai.com/p/state-of-context-engineering-in-2026
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

## Качество и надёжность

### Обвязка для долгих агентных задач (harness)
- **id:** `long-running-harness`
- **Тип:** метод
- **Что это:** рецепт Anthropic для задач на много сессий: агент-инициализатор пишет список фич в JSON (все «не готово»), рабочий агент берёт **одну фичу за раз**, ведёт файл прогресса и делает коммиты с понятными сообщениями, проверяет фичи end-to-end, как человек.
- **Механизм:** каждая новая сессия начинается без памяти; файл прогресса + git-история дают ей состояние без дорогого «переоткрытия» проекта; список фич не даёт объявить работу готовой раньше времени.
- **Статус:** active
- **Источники:** https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Оценки (evals) до оптимизации
- **id:** `agent-evals`
- **Тип:** метод
- **Что это:** до смены модели/промпта/архитектуры зафиксировать набор реальных примеров и критерии успеха, и после изменений прогонять его снова.
- **Механизм:** без измерения «улучшение» неотличимо от случайности; Anthropic отдельно показала, что шум инфраструктуры заметно влияет на результаты агентных бенчмарков.
- **Статус:** active
- **Источники:** https://www.anthropic.com/engineering (Demystifying evals for AI agents, 09.01.2026; Quantifying infrastructure noise in agentic coding evals, 05.02.2026)
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

### Subagents для изоляции контекста — только при реальной пользе
- **id:** `subagents-isolation`
- **Тип:** метод
- **Что это:** отдельные агенты читают много материала каждый в своём контексте и возвращают выжимку главному.
- **Механизм:** главный контекст не засоряется. Цена: по оценке Anthropic агент тратит ~4× токенов чата, multi-agent система ~15×; плохо подходит для задач с сильными зависимостями частей (большинство задач программирования).
- **Статус:** active
- **Источники:** https://www.anthropic.com/engineering/multi-agent-research-system
- **Добавлено:** 2026-10-07 · **Проверено:** 2026-10-07

## Экономия лимита подписки (чат Claude и Claude Code)

Для тех, кто работает по подписке (Pro / Max / Team): здесь экономятся не деньги за токены, а 5-часовой и недельный лимиты. Чат, Claude Code и задачи по расписанию тратят один общий лимит.

### Повторяющиеся материалы — в проект, а не в каждый чат
- **id:** `sub-projects-cache`
- **Тип:** метод
- **Что это:** документы и инструкции, к которым вы возвращаетесь, загружать один раз в проект (Projects), а не прикладывать в каждый чат.
- **Механизм:** [вендор] документы проекта кэшируются, и при повторном использовании «кэшированные части меньше расходуют лимит». Кэш истекает после периода бездействия — после долгого перерыва содержимое снова считается полностью.
- **Как применять:** основные рабочие документы загрузить в проект в начале работы; длинные постоянные инструкции — в инструкции проекта.
- **Статус:** active
- **Источники:** https://support.claude.com/en/articles/9797557-usage-limit-best-practices
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Одно полное сообщение вместо переписки
- **id:** `sub-complete-messages`
- **Тип:** метод
- **Что это:** заранее продумать запрос, дать весь контекст сразу, собрать связанные вопросы в одно сообщение, перечитать перед отправкой.
- **Механизм:** [вендор] каждое уточнение — ещё один полный запрос; меньше «туда-обратно» — меньше расход. Для кода: окружение и весь нужный фрагмент кода сразу; для текстов: аудитория, требования и весь текст в одном сообщении.
- **Статус:** active
- **Источники:** https://support.claude.com/en/articles/9797557-usage-limit-best-practices
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Новый чат для новой темы; длинная сессия дорожает
- **id:** `sub-fresh-context`
- **Тип:** метод
- **Что это:** не продолжать один бесконечный чат: для несвязанной задачи начинать новый чат (в Claude Code — `/clear`, перед этим `/rename`, чтобы потом вернуться через `/resume`).
- **Механизм:** [вендор] с каждым запросом заново отправляется вся история разговора, поэтому даже короткий вопрос в «многочасовой» сессии тратит лимит за весь разговор. Кэш на подписке живёт около часа: первое сообщение после перерыва дольше часа обрабатывает весь контекст заново по полной цене. `/compact` (сжатие) сам по себе тоже большой запрос; `/clear` ничего не стоит.
- **Статус:** active
- **Источники:** https://code.claude.com/docs/en/costs
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Модель и «глубина размышлений» под задачу
- **id:** `sub-model-effort`
- **Тип:** метод
- **Что это:** для простых задач — более лёгкая модель (Sonnet вместо Opus, Haiku для простых подзадач) и меньший уровень усилия (`/effort`).
- **Механизм:** [вендор] «размышления» модели оплачиваются как выходные токены, и по умолчанию это могут быть десятки тысяч токенов на запрос; Sonnet справляется с большинством задач программирования дешевле Opus. У моделей 5.5 и Fable размышления выключить нельзя — регулируется только уровень усилия.
- **Ограничения и риски:** общий лимит подписки один на все модели — при исчерпании переключение модели не спасает.
- **Статус:** active
- **Источники:** https://code.claude.com/docs/en/costs
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Меньше «постоянного груза» в контексте
- **id:** `sub-lean-base-context`
- **Тип:** метод
- **Что это:** отключать неиспользуемые подключения (MCP/коннекторы), держать CLAUDE.md коротким (до ~200 строк), а инструкции для отдельных процессов переносить в Skills; где есть консольная утилита (`gh`, `aws`) — она экономнее MCP-сервера.
- **Механизм:** [вендор] CLAUDE.md загружается в каждый запрос целиком, Skills — только когда нужны; MCP добавляет в контекст названия инструментов и инструкции серверов. Посмотреть, что занимает место: `/context`.
- **Статус:** active
- **Источники:** https://code.claude.com/docs/en/costs
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Скрытые потребители лимита и где их видно
- **id:** `sub-hidden-consumers`
- **Тип:** метод
- **Что это:** знать, что тратит лимит без вашего участия, и проверять расход.
- **Механизм:** [вендор] задачи по расписанию срабатывают и тратят лимит, даже когда вы не работаете; каждый субагент отправляет свои запросы сверх основного разговора; «команда агентов» тратит примерно в 7 раз больше обычной сессии. Где смотреть: claude.ai → Settings → Usage (5-часовое окно и неделя); в Claude Code — `/usage` с разбивкой по скиллам, субагентам, MCP и задачам по расписанию.
- **Как применять:** раз в неделю смотреть Settings → Usage; лишние задачи по расписанию выключать.
- **Статус:** active
- **Источники:** https://code.claude.com/docs/en/costs · https://support.claude.com/en/articles/9797557-usage-limit-best-practices
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

### Сначала план, рано останавливать неверный путь
- **id:** `sub-plan-and-stop-early`
- **Тип:** метод
- **Что это:** для сложной задачи сначала попросить план (в Claude Code — режим plan), формулировать запрос конкретно, при уходе не туда — сразу остановить (Esc) и откатиться (`/rewind`).
- **Механизм:** [вендор] расплывчатый запрос («улучши код») запускает широкий просмотр файлов; неверное направление, замеченное поздно, — это переделка, оплаченная дважды. Конкретные критерии проверки (тесты, ожидаемый результат) позволяют модели поймать ошибку самой.
- **Статус:** active
- **Источники:** https://code.claude.com/docs/en/costs
- **Добавлено:** 2026-10-08 · **Проверено:** 2026-10-08

## Знания и контекст

### LLM Wiki: база знаний, которую поддерживает агент (подход Карпатого)
- **id:** `llm-wiki-karpathy`
- **Тип:** метод
- **Что это:** ИИ-агент «компилирует» источники в вики из связанных markdown-страниц (сущности, концепции, сравнения) с каталогом `index.md`, журналом `log.md` и правилами в `CLAUDE.md`/`AGENTS.md`; сырые источники лежат отдельно и не меняются. Три операции: загрузка источника (ingest), вопрос (query — ценные ответы сохраняются обратно в вики), проверка здоровья (lint — противоречия, устаревшее, сироты).
- **Механизм:** знание обрабатывается один раз и накапливается, вместо повторного поиска по кусочкам документов при каждом вопросе (RAG); при умеренном объёме агент находит нужное через индекс, без эмбеддингов и векторной базы; «бухгалтерию» (ссылки, согласованность) ведёт агент, поэтому базу не забрасывают.
- **Когда полезно:** личная или командная база знаний, долгие исследования, «второй мозг» по теме; [вендор] одного индекса хватает примерно до 100 источников и сотен страниц, дальше — локальный поиск (например, qmd).
- **Ограничения и риски:** ошибка агента расползается по связанным страницам — нужны неизменяемый слой источников, Git, пометка происхождения у фактов и периодическая проверка человеком; idea file намеренно абстрактный, качество зависит от реализации; на миллионах документов не заменяет векторный поиск.
- **Статус:** active
- **Источники:** https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f · https://x.com/karpathy/status/2039805659525644595 · [вторичный] https://venturebeat.com/data/karpathy-shares-llm-knowledge-base-architecture-that-bypasses-rag-with-an
- **Добавлено:** 2026-10-09 · **Проверено:** 2026-10-09
