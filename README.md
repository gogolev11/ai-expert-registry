# AI Expert Registry

Реестр ИИ-инструментов, моделей, репозиториев и методов для личного ИИ-консультанта
(проект «ai expert» в Claude, скилл `ai-stack-architect`).

Консультант читает этот реестр перед ответом, чтобы опираться на проверенные и датированные
данные, а не на память модели.

## Как устроено

```text
Каждое воскресенье 09:50 МСК (scheduled task в Claude)
  └─ читает PROCESS.md, CRITERIA.md, SOURCES.md и реестр
  └─ ищет новое, отбирает 0–10 действительно значимых находок
  └─ открывает Pull Request — в main сам НИЧЕГО не пишет
        └─ вы смотрите PR → Merge = одобрено
           (выборочно: ответьте в сессии задачи «убери №3» или прокомментируйте PR)
```

Почему воскресенье 09:50: недельный лимит Claude сбрасывается в понедельник 10:00 МСК,
задача тратит остаток, который всё равно сгорел бы, и оставляет сутки на перезапуск.

## Файлы

| Файл | Что внутри |
|---|---|
| `registry/models.md` | Модели (флагманские, бюджетные, open-weight, специализированные) |
| `registry/products.md` | Продукты, сервисы и фичи ИИ-компаний |
| `registry/repos.md` | GitHub-репозитории (с метками INSTALL / ADAPT / STUDY / WATCH / AVOID) |
| `registry/skills-plugins-mcp.md` | Стандарты и экосистема Skills, plugins, MCP |
| `registry/methods.md` | Подходы: экономия токенов, качество, эффективность |
| `registry/archive.md` | Удалённые записи — с датой и причиной (ничего не исчезает бесследно) |
| `CRITERIA.md` | Что считается «супер значимым» |
| `SOURCES.md` | Где искать новое |
| `PROCESS.md` | Пошаговый регламент еженедельного обновления |
| `CONSULTANT.md` | Как консультант пользуется реестром |
| `CHANGELOG.md` | История изменений |

## Формат записи

```markdown
### Название
- **id:** `kebab-case-id`
- **Тип:** модель / продукт / фича / репозиторий / стандарт / метод
- **Что это:** 1–2 предложения простыми словами
- **Когда полезно:** для каких задач выбирать
- **Ограничения и риски:** честно
- **Статус:** active | watch
- **Метка:** INSTALL / ADAPT / STUDY / WATCH / AVOID — только для репозиториев и плагинов
- **Источники:** ссылки (первоисточник первым); [вендор] / [вторичный] пометки
- **Добавлено:** ГГГГ-ММ-ДД · **Проверено:** ГГГГ-ММ-ДД
```

Цифры (цены, звёзды, контекст) верны на дату «Проверено». Перед важным решением — перепроверить.

## Открыть в Obsidian

Реестр — обычные markdown-файлы, поэтому открывается в Obsidian без конвертации:
склонируйте репозиторий и выберите папку как хранилище (Open folder as vault) — или положите
клон внутрь своего хранилища. Обновление — `git pull`. Правки — только через ветку и PR.

Личные заметки, черновики и сырые материалы (например, из закрытых подборок) держите
**вне** этого репозитория: он публичный.

## Правила, которые нельзя нарушать

1. Добавление и удаление — только через PR и ваше одобрение.
2. Удаление = перенос в `registry/archive.md` с причиной, а не стирание.
3. Не больше 10 новых записей в неделю; 0 — нормальный результат.
4. Репозиторий не получает метку `INSTALL`, пока его код и инструкции не прочитаны полностью.
